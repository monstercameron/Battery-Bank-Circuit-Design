## The standing goal
> Start building the board and enter a refinement loop with an adversarial subagent to critically review the design and send it back for repair. Use a 3:1 safety buffer and focus on debuggability. Find board design docs and add them in /docs for later reference. Focus on quality, safety and ease of pick and place at JLCPCB, using their rules where applicable. Aim to make all these functions work at the same time, from battery and power pass-through (USB, barrel jack or PoE).

**Ground rules**
- **3:1 safety margin** applies to current, power and thermal only (not voltage).
- **Voltage derating:** MLCC ≥ 2×, FET/diode ≥ 1.5×. See `docs/design-rules.md` §1.
- **Reviews:** each round uses Claude reviewers **plus** a Codex `gpt-6.2-astra` adversarial reviewer. Memory note: `codex-adversarial-reviewer`.

### USB-C agent: done (report received after commit 5b62cbb; its last edits are uncommitted)
**Result:** the four `usbc_port_k` sheets have 0 errors. A full build of the whole tree still had 2 errors, R215 (`power_input`) and R374 (`dc_output`), both from the new resistor-dissipation check, in other agents' files.

**What changed in `usbc_port.py`:**
- **VBUS switch:** PD-controlled bidirectional switch (LM74502 driving back-to-back NTMFS5C628NL), with dV/dt control, OV cut-off at about 31 V, and a 24.9k connector bleed.
- **Charger I²C:** moved onto the TPS26750's private I2Cc bus (BQ at 0x6B, EEPROM at 0x50). The ESP32 now reaches each BQ only through TPS26750 I2Cr/I2Cw commands, and mux channels 0–3 are unused.
- **Dead-battery start:** the protection, EEPROM and pull-ups are powered from the TPS26750 LDO_3V3 (4.1 mA of the 5 mA budget).
- **Input current limit:** switched by GPIO. Default before a contract is 0.45 A max, then 3.54 A, then 4.94 A.
- **Feedback:** 249k / 20.0k 0.1 % divider; high corner 20.90 V.
- **Bulk:** about 89 µF effective per side, behind the switch. The connector side is about 2 µF.
- **Inductor:** YSPIT1510A-8R2M (25 A rated, 32 A saturation), so 3:1 holds at 7.42 A RMS.
- **Firmware duties:** GPIO map and firmware duty notes added to the sheet.
- **VSYS rename prep:** `STAGE_BUS = "VBAT"` is a single constant.

### Lead-owned tooling changes made just before the pause
These are **compiled but not yet exercised by a full build.**
- **`hardware/gen/build.py`**
  - **X-36 staged builds:** builds go to `<out>.staging` and are promoted only when the checker **and** KiCad ERC both pass. `--only` builds default to `hardware/kicad_partial/`.
  - **X-36 shared library:** `bb.kicad_sym` is now a merged union of symbols, written atomically.
  - **X-35 ERC gating:** KiCad ERC errors fail the build; `kicad_outputs()` returns the error and warning counts. A missing kicad-cli is an error unless `BB_SKIP_ERC=1`.
- **`hardware/gen/kicad_writer.py`**
  - **X-41 resolver rules:** `Part.resolve()` lets pin-number keys win, rejects conflicting assignments and dead name keys, and rejects NC on a connected pin.
  - **X-41 label IDs:** label UUIDs are seeded per project/sheet/ref/pin.
- **`hardware/checks/check.py`**
  - **X-34 resistor power:** resistors with no `Op_P` get a computed worst-case V²/R check (`3TO1R`).
  - **X-34 unknown stress:** resistors between equal non-zero rails are reported as INFO (stress undetermined).
- **`.gitignore`:** ignores `hardware/*.staging/` and `hardware/kicad_partial/`.

**Expect the first full build after these changes to surface new errors.** Fix the design (or set a justified `Op_P`), not the checker. Known cases:
- Cartridge ERC had 3 errors on U2 TLV70433.
- `3TO1R` will flag low-value resistors from high rails, e.g. PoE R141/R144.
- The resolver may now reject pin-key conflicts that used to pass silently.
